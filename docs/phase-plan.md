# Phase plan
Status values: `TODO` · `IN PROGRESS` · `DONE`. Exactly one phase is `IN PROGRESS`, **except P4 and P5, which run in parallel (user decision, 2026-11-02; P5 reached `DONE (demo scope)` on 2026-11-02, P4 still runs), and P6, which starts while P4's learning-curve runs and paperwork finish (user decision, 2026-11-02; file work only, no GPU, nothing P6 needs from P4 is still open: the payload carries two bands and no per-region definition, ADR-053 Amendment 6)**.
Each phase ends with the end-of-phase protocol in `CLAUDE.md` (logs, ADRs, mistakes, tag). `/sensei` -> `learn/phase-NN/` only for the major phases: P3, P4, P5, P6.

**Track A — demo (P0–P7):** capture -> data + baseline -> **Siamese CNN** -> **muscle definition** -> RAG -> agent -> deploy.
**Track B — best (P8–P10):** real data, product depth, hardening. Do not start B until A is live.
Data rule (ADR-020): demo models train on **BodyM + synthetic only**. Real photos come in P8.
Hosting (ADR-028): web on Vercel, API on **Google Cloud Run free tier**, models on Google Cloud, not HF Hub (ADR-043). The deploy spike and billing safety (budget + kill switch) are deferred to deploy time (ADR-031) but come before the first deploy; see the block inside P2 and the first P7 item.
**Goal input has two modes (ADR-025..027).** Mode 1, goal photo (usually front-only): **priority, ships in P7** (touches P3, P4, P7). Mode 2, "describe your goal" (text -> archetype table): **P9 only, must not delay P7**; its single pre-deploy cost is the P4 render-params + masks save.
